# Design (agreed 2026-11-07, reviewed with Gemini)

Product name: **FC26 Career MCP** (author GLOUNDEV, repo github.com/Jeong3954/fc26-career-mcp). MCP server slug `fc26-career-mcp`, tool prefix `fc26_`.
Unofficial: not affiliated with or endorsed by Electronic Arts / EA SPORTS; FC 26 Live Editor is by xAranaktu. Read-only. Offline career mode only. No anti-cheat bypass.

## Pieces

| Path | What | Runs where |
|---|---|---|
| `bridge/fc26cm_bridge.lua` | Lua script for FC 26 Live Editor (Lua Engine). Read-only, autorun-safe, bounded. Writes JSON files. | inside the game (via Live Editor) |
| `bridge/fc26cm_bridge_autorun.lua` | Same file with `local AUTORUN = true` (generated by `tools/build_autorun.py`). Installed into `<LE>\lua\autorun\`. | inside the game |
| `save/save_reader.py` | Parses a COPY of the newest career save offline (vendored MIT parser `save/vendor/fc26_mcp/`). Writes `save_extract.json`. | user's PC, called by the server |
| `server/fc26cm_mcp.py` | Local stdio MCP server (stdlib only). Reads the JSON files, never the game. | user's PC, started by the MCP client |
| `skill/SKILL.md` + `skill/references/` | How an LLM should use the tools; accuracy rules. | the LLM |
| `installer/install.py`, `uninstall.py`, `healthcheck.py` | Run by the user's AI agent (INSTALL_FOR_AI.md) or by hand: detect, copy the Lua to the LE autorun folder, data folder + config, register in every detected client by JSON merge (TOML for Codex), health check with PASS/FAIL lines. No wizard, no .exe. | user's PC |
| `server/fc26cm_http.py`, `server/fc26cm_cli.py` | Streamable HTTP MCP + REST/OpenAPI on 127.0.0.1:26261; CLI text summaries for assistants without MCP. | user's PC |
| `INSTALL_FOR_AI.md`, `AGENTS.md`, `docs/CLIENTS.md` | Agent install guide (deterministic steps, branches per client), client-neutral usage rules, compatibility matrix + snippets. | the user's LLM |
| `tests/` | unittest, sanitized fixtures for manager and player careers. No game needed. | anywhere |

## Data folder

Default `%USERPROFILE%\Documents\FC26CareerMCP\`. Optional redirect: `%USERPROFILE%\Documents\FC26CareerMCP\config.json`
`{"data_dir": "D:\\somewhere"}` (written by the installer; the bridge and the server both honour it). No environment variables.

Files written by the bridge (all atomic: `.tmp` + rename):

| File | Content | When |
|---|---|---|
| `status.json` | `{schema:1, product, bridge, le_version, compat: "full"|"partial"|"unsupported", memory_reads: bool, reason, supported_le_versions:[...], mode, written}` | bridge start, every career load |
| `heartbeat.json` | `{bridge, wall, unix, reason, career_ready, why, mode, game_date, date_error}` | every career event |
| `snapshot.json` | schema 4 (see below) | first read, every game day, after each user match |
| `world.json` | `fc26-world-1`: `tables[]` (every standings group), `top[]` (top 10 per competition: goals, assists, clean_sheets, avg_rating), `fixtures[]` (all clubs, played + upcoming, caps), `transfers[]` (market-wide, cap 400), `club_transfer_finance[]` | first read, once per game day. BOTH modes. |
| `event_payloads.jsonl` | raw event payload dumps (cap 8 MB) | every event |
| `last_step.txt` | breadcrumb | before risky steps |

The in/out request channel of the internal bridge is REMOVED: tools only read files. `fc26_status` tells the LLM how to refresh (advance a day / open the hub).

### snapshot.json schema 4 (keys added to schema 3, nothing renamed)

Common: `schema=4, product, bridge, le_version, compat, memory_reads, reason, written, game_date, date_error, game_date_source,
mode: "manager"|"player"|"unknown", user{name, firstname, seasons, club_teamid, usertype, playertype}, user_team{id,name},
transfer_budget, wage_budget (null = no getter), last_results[], next_fixtures[], next_fixture, league_table{competition, compobjid, rows[], team_competitions[]},
squad{count,total_wages,players[],excluded[],notes,...} (both modes), events[] (filtered names, GLOBAL), event_payloads[] (decoded, scope ours|global), raw_events[]`.

Manager only: `transfers[]` (user club this season), `offers[]` (open, received), `offers_history[]`, `bids[]` (sent), `player_talks[]`, `targets[]`
(player detail for ids referenced by offers/bids/talks that are not in the squad: playerid, name, team, age, position, overall, potential, attributes),
`offers_read_at, offers_error, pending_reads[], last_job`.
Raw negotiation words (`raw`, `raw_loan_offer`) are NOT in the product snapshot.

Player only: `user_player{playerid, name, team_id, team, position, age, overall, potential, wage, season_count, attributes{38 attrs + skillmoves, weakfoot, foot, height, weight},
recent_ratings[] (rating_int_5_10), avg_rating_recent, season{app,goals,assists,yellow,red,by_competition[]},
career{playerrequest, numtransferrequests, numloanrequests, numwithdrawrequests, requestactiondays, lastwithdrawdate, playedlastmatch, position} (career_playasplayer),
history[] (career_playasplayerhistory rows: season, teamid, appearances, goals, assists, motm, matchratings, cleansheets, wins, draws, loses, wage, overall, value, tableposition, leaguetrophies, domesticcuptrophies, continentalcuptrophies, clublevel),
last_match{mins,pos,ovr}, squad_role: "not_available"}`.

Negotiation action codes (manager): 6 = buyer offer, 2 = seller counter (asking terms), 3 = seller on hold, 0 = seller accepted, 4 = buyer accepted, 1 = rejected, 5 = expired/ended by buyer.
Open = last code 6 or 2 (or 3). Closed = 0/4 accepted, 1 rejected, 5 expired.

### Version gate

`SUPPORTED` table at the top of the Lua: LE_VERSION -> offsets block. Unknown LE_VERSION => `compat: "partial"`, memory reads disabled for the
session (no standings/fixtures/league table/transfers/offers/world fixtures/tables), documented API reads continue (DB getters, GetPlayersStats, names).
Canary checks before every memory walk (pointer validity, list sizes <= 8000, vector sizes <= 4000, id ranges); a failed canary disables memory reads for the session (`compat: "partial"`, reason).

## MCP tools (8)

Every response = `{"_meta": {...}, ...data}`. `_meta = {source: "live"|"save"|"live+save", scope: "user_club"|"user_player"|"global"|"mixed", mode,
live_game_date, snapshot_written, snapshot_age_sec, heartbeat_age_sec, save_as_of (when save used), compat, warnings[]}`.
Rules are baked into tool descriptions and field names (explicit home/away keys, `rating_int_5_10`, `scope` on events). No write tools, no raw Lua, no table dumps.

| Tool | Args | Manager | Player |
|---|---|---|---|
| `fc26_status` | - | freshness, versions, compat, mode, how to refresh, which files exist | same |
| `fc26_my_career` | - | club overview: user, team, budgets, league position + table slice, last results, next fixtures, squad counts, open offers count, pending reads | user player profile (attributes, ratings, season stats, career requests, history) + club context |
| `fc26_squad` | `include_attributes?` | squad with contracts, ratings, injuries, flags, season stats + save extras per player (suspensions, loans, presigned, youth graduate) | same (club squad; contract fields may be absent) |
| `fc26_player` | `playerid` or `name` (exact/partial match within known names; ambiguous => list) | squad player full detail; transfer target detail (`targets`); others: world top-list rows only + save extras (previous clubs, grudge/love) | same (user player via `fc26_my_career`) |
| `fc26_competitions` | `view: standings|fixtures|top_players`, `compobjid?`, `teamid?`, `last?`, `next?`, `stat?` | all competitions from world.json; default compobjid = the user's league | same |
| `fc26_transfers` | `teamid?`, `scope: user_club|market`, `include_history?` | user club transfers, open offers (decoded stages), offers history, our bids, player talks, targets; or market-wide transfers + club finance | club transfers + market; `user_player.career` requests (transfer/loan/withdraw) |
| `fc26_save_data` | `category: national_teams|managers|board_history|suspensions|loans|presigned|youth|grudge_love|previous_clubs|summary`, `teamid?` | from save_extract.json (refreshes when the save changed), identity-checked against the live snapshot, names hydrated from live maps | same |
| `fc26_global_events` | `days?`, `kind?` | filtered event names (GLOBAL, never attributed) + decoded payloads with scope | same |

Player career mode: `fc26_transfers` returns `offers: null` with `not_available_reason`.

## Save reader

- Newest `CmMgrC*` (manager) or `CmPlyC*` / other `Cm*` career files under `%LOCALAPPDATA%\EA SPORTS FC 26\settings\`; size-stable (200 ms) before copying; parse the copy.
- Identity check: `career_users.userid/clubteamid` (and the player id in player careers) must match `snapshot.user`; mismatch => `error: different_career`.
- Output `save_extract.json` schema 2 = schema 1 keys + `national_teams[]` (leagueteamlinks leagueid 78 men / 2136 women -> teams + teamplayerlinks rosters),
  `managers[]` (manager table: managerid, name, teamid, nationality, birthdate), `career_type`, `user_player` (player careers).
- Names: the save has no real player names; the server hydrates ids from live name maps (snapshot + world). Unknown ids stay ids.

## Installer (revised 2026-11-07: owner decisions after the Gemini review)

No setup .exe / wizard. Distribution = a GitHub repository whose README says "paste this prompt into your
LLM"; the user's own AI reads `INSTALL_FOR_AI.md` and does the install: detect Live Editor / Python / the
client it runs in, back up, copy the bridge (an existing bridge-like script in `lua\autorun\` such as a
personal `le_bridge_ro_auto.lua` is detected and the human is asked: `--allow-coexist` or move it), create
the data folder, register the stdio server by JSON merge in each detected client (`claude mcp add` /
`codex mcp add` when their CLIs exist; TOML block for Codex otherwise; VS Code uses `servers` +
`type: stdio`), optional `--http-autostart` Startup entry for the HTTP server, `healthcheck.py` with plain
PASS/WARN/FAIL/SKIP lines, `uninstall.py` reversing everything (data folder kept unless `--purge`).
The human only pastes the prompt and does the in-game steps (start through Live Editor, open the career
hub, restart the client).

## Any LLM

MCP stdio for clients that start a command; MCP Streamable HTTP (stateless JSON responses, localhost) for
clients that take a URL; REST JSON + OpenAPI and a `/text/<tool>` endpoint and `fc26cm_cli.py` for
assistants without MCP (ChatGPT: paste mode; it only connects to remote HTTPS MCP servers). `AGENTS.md`
carries the rules for non-Claude clients; `skill/SKILL.md` for Claude. Matrix: `docs/CLIENTS.md`.
